## #1 · One truth for the gala & money numbers — `gala-ops.js` + `money.js` (backend) + `gala.js` + `money.js` (views)

**The single computation.** `backend/v2/gala-ops.js` gains module-scope `computeGalaSummary(db)`
(and `computeGalaPrice(db)`), written standalone — it takes the db getter as its argument and
touches no mount closure, so any module can call it. It returns one labelled shape:

```
{ basis: 'seats', price, seats: { reserved, paid, chase, seated, capacity },
  bookings: { total, paid, chase }, eur: { collected, outstanding }, cancelled, now }
```

`seats` counts **1 + guest_count** (plus-ones included) over rows whose status is not
cancelled/rejected/declined/expired; `bookings` counts registration rows, i.e. payments. Both bases
travel together so a screen can state either and name which it used.

**Served three ways, computed once:**
- `GET /api/v2/gala-ops/summary` (auth + adminOnly) — new route.
- embedded as `summary` in the existing `GET /api/v2/gala-ops/overview` payload (no extra round trip
  for the Gala screen).
- exported as `module.exports.computeSummary` / `.computePrice` — `backend/v2/money.js` requires
  `./gala-ops.js` defensively (`try/catch`, `galaTruth`) and uses it for the `gala_unpaid` line of
  `moneySummary()`. A missing export can only fall back to the old local SQL, never crash the mount.

**Divergent local math killed, in the files A3 owns:**
- `gala.js` `stats()` now reads `D.ops.summary` (the overview's embedded canonical block). The old
  row-walking arithmetic survives only as the fallback for a failed overview read — it is the
  identical formula, kept as a degraded path, not a rival one.
- `backend/v2/money.js` `moneySummary()` no longer re-derives the unpaid gala figure. It used to
  count **rows** (`COUNT(*) … payment_status != 'paid'`) at its own `galaPriceByClock()`; it now takes
  `seats.chase` and `eur.outstanding` from the shared computation. That row-vs-seat split *was* the
  audit's €5,250 / €5,100 gap: on the stub fixture (one paid single, one unpaid guest+1, one
  cancelled) the old path yielded 1 × €150 and the Gala screen said 2 seats / €300. Both now say
  **2 seats · €300**, and the summary reports `gala: { …, basis: 'seats', shared: true }`.
- The owed line is relabelled `"Neplaćena Gala mjesta × 150 € · unpaid seats incl. plus-ones"` — the
  basis is on the stat, per the audit's prescription.
- Gala KPI sub-lines now name their basis: "seats spoken for · incl. plus-ones", "seats paid ·
  €X collected", "seats unpaid · €X outstanding", "of N seats · rest unassigned".

**The remaining three screens (not A3-owned) — each is now one fetch away.** They should read
`GET /api/v2/gala-ops/summary` and delete their local walks:
- `js/views/today.js` (`Admin Home › "Hero numbers"`, ~lines 123–137): counts **bookings**
  (`paid.length`, `toChase.length × price`) and labels them as if they were seats — the "27 paid ·
  €5,250" card. Swap to `summary.seats.paid` / `summary.eur.outstanding`, or keep bookings and say
  "27 **payments**".
- `js/views/plexus.js` (`Admin Plexus Hub › "Stat strip + key dates"`, ~lines 160–174): same
  booking basis **and** its `toChase` filter omits the cancelled/rejected exclusion
  (`galaRows.filter(g => g.payment_status !== 'paid')`), so cancelled seats are still chased — the
  "26 paid · 9 to chase" card. This one is a correctness bug, not only a vocabulary mismatch.
- `js/views/eventday.js` + `backend/v2/host-brief.js` (`Admin Event Day › "Counters"` + v2
  `"HOST BRIEF"`): the door card's "4 of 39 expected" is a per-gate expected count while the Host
  Brief's "IN 4 of 51" is people-including-plus-ones. Either share `summary.seats.reserved` as the
  denominator or keep both and say why in the sub-line. UXFIX-A1 explicitly left these unchanged
  (its "Known interactions" note), so no edit collides.

## #8 · Links: the `/plexus/null` bug, bulk archive, duplicate collapse — `links.js` (view + backend) + `links.css`

**The null at its source.** Traced: `POST/GET /api/admin/registration-links` in `server.js`
(~36329 and ~36362) build the shareable URL as `` `${userPortalUrl}/plexus/${l.token}` `` for
`event_type === 'plexus'`. A row whose `token` is NULL — legacy rows, and the `combo-links`
path at ~31049 which inserts its own `registration_links` row — interpolates the string `"null"`,
producing a live-looking `/plexus/null` that opens nothing. `server.js` is outside the A3-owned set,
so the fix lands on both sides of it that A3 does own:
- **Creation refuses it.** `createLink()` inspects the POST response; if the returned link matches
  `/\/(null|undefined)$/` or a plexus link came back without a token, it immediately deactivates the
  row through `POST /api/v2/links/:kind/:id/active {active:false}` and toasts
  "THE SERVER MINTED A LINK WITHOUT A SLUG (…/null) — ARCHIVED IT ON THE SPOT, NOTHING TO SHARE".
  No slugless link is ever presented as shareable.
- **Existing ones are quarantined, not listed as live.** `load()` flags `broken` on any row whose URL
  ends in `/null` (or `/undefined`), plus registration rows with no token.
- Server-side hardening of the builder itself (refuse to insert a slugless plexus row) belongs to
  whoever owns `server.js` — noted, not done here.

**ARCHIVE section.** `archived = paused || expired || broken`. The LIVE LINKS list shows only the
rest; the others collapse into a `ARCHIVED (N)` disclosure with a per-row reason chip
(BROKEN / EXPIRED / PAUSED), the broken chip carrying the explanation on hover, and RESUME still
available for merely paused rows. Nothing is deleted — link history is sign-up history.

**Bulk archive.** Every row gets a checkbox; ticking any shows `ARCHIVE N SELECTED`, which confirms
and calls the new **`POST /api/v2/links/bulk-archive`** (auth + adminOnly, ≤200 items,
`{ items: [{kind, id}] }` → `{ archived, failed: [{kind, id, error}] }`). Archive is exactly the
reversible pause the single toggle writes — `registration_links.is_active = 0`,
`gala_invite_links.revoked = 1`, `croatians_abroad_invite_links.revoked = 1` — audited per row as
`links.bulk_archive`. Per-row failures are reported, never silently dropped. No deletes, no new
tables, no ALTERs.

**Duplicate collapse (visual only).** Live rows sharing system + audience + name group together; the
canonical row is the one with sign-ups (most uses; ties → oldest) and carries a `+N DUPLICATES`
chip. Its twins render as one dimmed line reading **"duplicate of → «name»"**, ordered directly
under it, keeping their own count, PAUSE and checkbox. Nothing is merged or deleted — the operator
ticks the twins and archives them if they want them gone.

## #10 · Search: keyboard, clamp, operator vocabulary — `chrome.js`

- **`/` and ⌘K / Ctrl+K focus the box** (and select its contents) via one document-level keydown
  beside the existing Escape handler. `/` steps aside whenever an INPUT/TEXTAREA/SELECT or a
  contenteditable has focus; the chord works from anywhere. Alt-chords are ignored.
- **The popover clamps inside the viewport**: `left:auto; right:0; width:min(320px, calc(100vw - 32px))`
  on the `.mx-pop` — right-aligned to the search field with a 16px gutter each side, so it can no
  longer clip mid-word off a 1280px edge, and it fits a 390px phone.
- **Action names are indexed.** Palette entries carry a `syn` field of HR/EN operator vocabulary, and
  matching runs through `fold()` (lowercase, đ→d, NFD diacritic strip) on both sides, so "racun"
  finds "račun" and vice versa; every token must match, so multi-word queries narrow. New entries map
  the words operators actually type to destinations:
  invoice/račun → Money · Knjiga ulaznih računa (`/money/ulazni`) and Knjiga izlaznih računa
  (`/money/izlazni`); travel order/putni nalog → `/money/putni`; payment order/nalog za plaćanje →
  `/money/nalozi`; work unit/radna jedinica → `/money/jedinice`; report/izvještaj/export →
  `/money/izvjestaji`; owed/potraživanja/refund/chase → `/money/owed`; chase/refund/podsjetnik,
  seating/stol/raspored, kitchen/meal/jelovnik → `/gala`; approve/outbox/odobri → `/inbox`;
  badge/bedž/QR/scan/skener/door → `/event-day`. Existing screens gained synonyms too
  (ljudi, prijave, novac, kalendar, postavke, poveznica…). All targets are existing routes
  (`/money/:tab?` and `/gala/:tab?` already accept these tabs — `TAB_TARGET` in money.js resolves
  ulazni/izlazni/putni/nalozi/jedinice/izvjestaji/owed).

**Country normalized at render.** New `countryName()` in `people.js` (exported; `registrations.js`

## #14 · Gala seating: the truncated meal, and a board that accepts assignment — `gala.js` + `gala.css`

- **Meal dropdown.** New `mealShort()` renders the label's first segment (before any `/ · ( — –`),
  so "Meat / Standard" shows as `MEAT` instead of `MEAT / STANDA▾`. The full label rides the
  `<select>`'s `title` and each `<option>`'s title, and stays intact in MENU OPTIONS, the kitchen

  `min-width:0; text-overflow:ellipsis` in css. Nothing renames a menu option in the database.
- **The board is an input.** A table tile now opens a seat popover (`tileSeat`): who is already
  seated there, then the UNSEATED guests as tap targets — tap one and they are seated. It goes
  through the **existing** `POST /api/admin/gala/tables/:id/assign` (the seat_number mirror, so the
  wallet pass updates), exactly as the row dropdown and the UNSEATED chip already did. A full table
  says so instead of offering guests; an empty unseated list says everyone is placed. The old
  tap-to-filter behaviour is not lost — it is an action inside the same popover
  ("SHOW TABLE T3 IN THE LIST"). The ✎ table editor still opens from the tile corner. The row
  dropdowns stay as the fallback, and the board hint now reads "tap a table to seat a guest — the
  list dropdowns still work". **No endpoint was added, changed or removed.**
