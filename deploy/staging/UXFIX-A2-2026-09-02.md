## What changed

### #4 · Member messages: a guest can no longer wait invisibly

**The tab badge now counts what the tab is for.** The MEMBER MESSAGES tab had no badge; the Inbox pill counted only outbound batches. The tab now carries a **NEEDS A REPLY** count with a hover title ("3 member threads waiting for a reply").

The count deliberately is *not* "unread". A guest who asks for an invoice, whose thread someone opened and then closed without answering, is read and still waiting — that was the exact hole the audit found. The rule is the one the tab's own NEEDS A REPLY filter already applies: **not archived, and (unread > 0 or the last message is theirs)**. Backend and frontend state that rule in one place each and are kept in step by name (`countNeedsReply` / `GET /needs-reply`).

- **New route (additive, read-only):** `GET /api/v2/inbox/needs-reply → { count }`. Auth + adminOnly like its neighbours. Honours this admin's archive state, including the existing reopen-on-newer-message rule — but unlike `GET /threads` it performs no write, so a badge poll cannot mutate anything.
- **Degrades cleanly:** against an older backend the view falls back to the loaded threads (on the messages tab) or to the plain unread count, which is a floor rather than an overcount.
- `reloadThreads()` and `openThreadByKey()` recompute it locally, so opening a thread clears its *unread* dot without falsely clearing its *needs a reply* state.

**Broken attachment previews.** Reproduced first: a stored `/uploads/messages/<file>` does not survive a redeploy — that disk is ephemeral and only the Cloudinary copy is permanent — so the message bubble rendered a browser broken-image glyph where a thumbnail should be. The thumbnail now removes itself on error (`onerror="this.parentNode.style.display='none'"`, the same pattern the Studio photo tiles already use) and the **labelled chip stays**, which is the part that actually opens or downloads the file. PDFs never had a thumbnail and are unaffected.

**Enter no longer sends a member-bound message.** The `keydown` handler that fired `sendReply` on a bare Enter is **removed**. Enter is now a newline; the SEND button is the only way a reply leaves the building. The placeholder changed from "Enter sends, Shift+Enter for a new line…" to "Write your reply — nothing goes out until you click SEND…" so the box no longer advertises the behaviour it no longer has.

**TEAM CHAT keeps Enter-to-send.** That surface is internal — a half-typed line reaching a teammate costs nothing. The distinction is stated in the code where the two handlers sit next to each other, so the next person does not "restore consistency" by mistake.

### #6 · Weekly pulses: the safe bulk action now exists

`DISCARD ALL n` sits beside `APPROVE ALL n` in the weekly-pulse group header, in crimson, behind a confirm that names the count and the consequence:

> **Discard the waiting weekly pulses?**
> Discards 9 stale drafts — nothing is sent. Everything already approved or sent stays exactly as it is.
> `KEEP THEM` · `DISCARD ALL 9`

It iterates the pending pulse batches through the **same** `POST /api/admin/outbox/:batch/cancel` the per-row DISCARD already uses. That route's `WHERE` clause only ever touches rows in `pending_approval`, and approved / scheduled / sent batches are not in `D.pending` to begin with — so **approved and sent history is untouched by construction, not by care**. DRAFTS & HISTORY keeps its record either way.

Offered only for the weekly-pulse group (the audit's pile-up), and only when more than one is waiting. Stale rows also gained an age flag — `8 WEEKS OLD` — so the reason to discard is visible before the click.

### #7 · Calendar: the year board is deleted, the space reclaimed

The Gantt board rendered the same eight entries as NEXT UP and KEY DATES — the page's own footer conceded it — with one-day events as unreadable 8px bars. Removed: `blockBoard()`, `boardRow()`, `monthHeader()`, `dateLine()`, the legend and TODAY-line copy, and the `.mxc-scroll` / `.mxc-grid` CSS hooks that existed only to let it scroll sideways.

Its two real jobs survive:

- **KEY DATES is now the main column** — first in the row and the wider one (1.35fr / 1fr, was 1.5fr / 1fr with tasks first). It already carried the colour keys and both years.
- **Entry deletion moved with it.** `✎ EDIT ENTRIES` now sits on the KEY DATES header and reveals a `✕` on rows that are real board entries, deleting the same row via the same `DELETE /api/admin/year-calendar/:id` with the same UNDO. Derived rows (conferences, bridges, FACTS gap-fills) have nothing to delete and correctly show no `✕`.
- **The 12-month grid still exists where it reads well:** the print board behind EXPORT PDF, untouched, still A4 landscape.

`+ ADD ENTRY`, EXPORT PDF, EXPORT CSV and TEAM TASKS are unchanged.

### #9 · One early-bird truth

`facts.js` already says **Sep 15** (`gala.priceFlip: '2026-09-15'`) and the live `gala_settings.early_bird_deadline` is the preferred read. The contradiction came from a **board entry**, not from copy: a `year_calendar_entries` row dated 2026-09-01 whose text described the same price switch, sitting directly above the live Sep 15 line.

Three things now hold:

1. **One canonical sentence.** An entry that describes the early-bird switch renders as `Gala early-bird ends — €150 → €175 (automatic)` on the live deadline, keeping its own id so `✕` still deletes the real row. When no entry covers it, the row is derived from live gala settings, falling back to FACTS.
2. **Strays are suppressed on every surface.** Entries whose date differs from the live deadline are kept out of KEY DATES, out of NEXT UP, and out of the **printed** board — the paper agrees with the screen.
3. **Strays can be removed for good, not just hidden.** A quiet gold strip under KEY DATES: *"One older calendar entry puts the same early-bird switch on a different date."* → `REMOVE IT`, behind a confirm that names the live deadline and says removing it changes no price and sends nothing, with UNDO after. Nothing is deleted silently.

Also fixed in this file: the announcement composer's placeholder read *"e.g. Gala early-bird ends September 1"* → now **September 15**.

**Deliberate exception:** `EXPORT CSV` still dumps every `year_calendar_entries` row, strays included. It is a record export, and a lossy one ("I have 6 entries, the CSV has 5") would be worse than a visible one. Once the stray is removed via the panel, the question disappears.

### #15 · Studio: the stored-files pointer card is gone

`STORED FILES` was an empty box whose own body text sent the reader to Settings → TEAM LIBRARY. Deleted: the block, its rows, its copy, the `KIND()` mime-label helper, the `storedOpen` download handler, and the now-pointless `/api/admin/files` fetch — the Studio no longer calls that route at all. The `session` and `perms` imports went with it (nothing else used them). PHOTO LIBRARY, BRAND ASSETS, the tool cards and every drawer are untouched.

## Notes for the deployer

- **Additive backend.** One new GET route; no DDL, no writes, no new tables, no change to any existing route or response shape. Boot order is irrelevant.
- **Safe with an older backend:** the tab badge falls back to the thread list or the unread count. **Safe with an older frontend:** the new route simply goes uncalled.
- **Nothing about sending changed.** No new send path, no change to approve, cancel, scheduling, or the drainer. The one new bulk action is a *discard*.
- The Sep 1 board row still exists in `year_calendar_entries` until an operator clicks REMOVE IT. It is invisible everywhere in the meantime.
