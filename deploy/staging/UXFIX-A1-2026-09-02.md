## #2 · Door list: one person, one row — `event-day.js` (backend) + `eventday.js`

- **Backend `doorRows()`** now runs a **DISPLAY-level merge per `lower(email)`** (new
  `mergeDoorRows()` helper) on the conference / gala / bridges / donor lists. A member holding
  Conference + Gala + a Croatians-abroad row appears **once**.
- **The admit contract is untouched.** The merged row keeps the **ref of the registration a scan
  of that person would admit** — push order in `doorRows()` is exactly the
  `findByEmailOrShort`/`fitForGate` lookup priority (gate-preferred table first, newest first), and
  the merge runs **before** the checked-in-last sort so that order is still authoritative.
  `admitted_count` / `party_size` stay the scan target's; CHECK IN / +1 drive the same
  `v2_checkin_admits` ledger a QR scan does. Other bookings: `merged_refs` + `merged_count`
  fields, and the meta notes "· N bookings" (+ "· N in on another booking" when an old-scanner or
  v2 admit exists on a non-primary ref). Rows without an email never merge. Nothing writes.
- **Unpaid gala guests**: new `unpaid` flag (gala door only: `payment_status` ∉ paid/vip-comp,
  CA `gala_payment_status` ≠ paid) + `amount_due` from new `galaDueNow()` (mirrors gala-ops
  `priceBlock()` arithmetic: gala_settings + event_components, early/regular by
  `early_bird_deadline`, fallback €150). Frontend renders a **crimson `€150 DUE` chip**
  (`COPY.door.due`) next to the button; hidden once the party is fully in.
- **Row layout** (`doorRowsHtml()`): one line, `min-height:44px` — name + dimmed meta inline with
  ellipsis (`min-width:0` flex), chip + state/button on the same line, never wrapped below. At
  ≤480px the name may take the full text line (css). All hooks kept: `data-door-ref`,
  `data-act="doorIn"`, `mx-row`, `mx-row-text`.
